Close WR-02: after Phase 02-02 wired `sortPlacementsByPosition`, the public article page still selects the Editor's Verdict by array index (`placements[0]`). Because the canonical sort puts `top_cta` first, the top CTA is always consumed as the mid-article verdict and can never render at the top, and a `middle_comparison` can never be the verdict when a `top_cta` exists. This makes ROADMAP SC #3's "attach at top/middle/footer positions that render in order" silently untrue.

Purpose: select the verdict by position (prefer `middle_comparison`), keep `top_cta` in the top/remaining slot, extract the mapping into a pure function matching the repo's pure-builder + unit-test convention, and unit-test it.

Output: `selectVerdictPlacement` in `src/lib/placement-order.ts`, an RSC call site using it, and coverage in `tests/lib/placement-verdict-order.test.ts`.
</objective>
