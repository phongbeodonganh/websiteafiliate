       - `cmsFetch<T>(path: string, options: { method?: string; body?: unknown; token?: string | null; signal?: AbortSignal }): Promise<{ ok: true; status: number; data: T } | { ok: false; status: number; message: string }>`.
         Behavior: when `body` is present set `Content-Type: application/json` and `JSON.stringify` it; attach `Authorization: Bearer <token>` whenever a token is supplied; parse the JSON response envelope; treat `ok === false` OR envelope `status === 'error'` as a failure result; never throw for an HTTP error (only for a genuine fetch rejection, which it converts to `{ ok: false, status: 0, message: <network copy> }`).
       - `errorMessageForResponse(status: number, serverMessage?: string): string` mapping exactly to the UI-SPEC Copywriting strings: 401 → the session-expired copy, 403 → the no-permission copy, 404 (on an edit load) → the article-no-longer-exists copy, 400 → `serverMessage` verbatim with the documented fallback, 500 → the server-error copy, 0 → the network copy, otherwise the generic fallback.

Create `tests/lib/cms-fetch.test.ts` with an injected/mocked `fetch` covering: header attachment when a token is present; no Authorization header when the token is absent; JSON body serialization + content-type; a 401 response → `ok:false` with the session-expired message; a 403 → the permission message; a 500 → the server-error message; a 400 carrying a server message → that message verbatim; a network rejection → `ok:false, status:0` with the network copy; and a 200 success envelope → `ok:true` with `data`. Assert the helper never throws for the HTTP-error cases.
