<objective>
Convert the canonical auth guard `getAuthUser` from synchronous (signature-only) to asynchronous with a database-backed active-status check, and await it at every call site. This closes the existing-token window for deactivated and deleted accounts (D-15, assumption A1) across the entire CMS surface at once.

Purpose: A deactivated account currently keeps a working session until its 24h JWT expires. Enforcing `status` in the single canonical guard locks the account out on the next request without duplicating the check in 27 routes.

Output: async `src/lib/auth.ts`, awaited guards in all 27 route files, an updated 401-gate control test, and a new inactive/missing-user regression suite.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bearer token → auth guard | A cryptographically valid token is untrusted until the principal's live DB status is confirmed |
| deactivated/deleted account → CMS surface | A stale session must not retain access after the account is disabled |
| guard → 27 route handlers | Every route delegates authorization to the one canonical guard |

| T-02-02 | Spoofing | token of a deleted user (missing document) | high | mitigate | missing document → null → 401 (Task 1, assumption A1) |
