# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** Phase 2 repairs the **already-deployed admin CMS** in `src/app/admin/page.tsx`. Its UI contract binds only the internal admin surface and the new controls added there (admin shell/tabs, article editor GEO/FAQ/taxonomy fields, user management, taxonomy management, blacklist import panel + Re-sweep, the shared auth-fetch error toast). It does **not** touch the public presentation layer — the Bento redesign is Phase 4. The public article page already renders FAQPage JSON-LD from `faq_schema`; no new public-side UI exists in this phase.

### Theme ruling — the admin surface keeps its existing dark shell theme (read before writing any UI)

There are **two visually distinct admin themes in the repo today**, and Phase 2 must not create a third:

| Theme | Lives in | Palette | Fate in Phase 2 |
|-------|----------|---------|-----------------|
| **Dark "luxury/cyber" shell** | `src/app/admin/page.tsx` (all 9 tabs), `src/app/admin/login/page.tsx` | canvas `#060608`, shell `#0a0a0c`, `slate-900/800` surfaces, **amber/gold** primary accent | **This is the admin contract.** Phase 2 edits it in place; it stays dark. |
| **V5.2 light palette** | `src/app/admin/articles/create/page.tsx` + `src/app/admin/articles/edit/[id]/page.tsx` | `#F8F9FA`, Royal Blue `#0056B3`, Coral `#FF6B6B`, Mint `#20C997` | **Both files are deleted in Phase 2 (D-02).** Deleting them removes the ONLY light-palette usage in `/admin`. |

**Ruling:** the V5.2 light palette MUST NOT be introduced into the admin surface in this phase. Reasoning:

1. `01-UI-SPEC.md` explicitly reserved the V5.2 light palette for Phase 4, NOT earlier phases. That still holds — more strongly — here.
2. The two files that used it are being removed (D-02). Introducing it into the shell would add a third theme for no user-facing reason and would pre-empt Phase 4's Bento/palette decision.
3. The admin CMS is an **internal tool with its own established identity** (dark shell, gold accent). It is not the public brand surface. Its dark theme is legitimate and independent of the public V5.2 palette.
4. The Tiptap editor's `.custom-editor-content` styles in `globals.css` are dark-surface styles (`#f8fafc` text on dark) — consistent with the dark shell, not with a light canvas.

Every new Phase 2 control is styled with the existing dark-shell token language below.

## Spacing Scale

Declared values (multiples of 4 only). These match the admin shell's existing Tailwind rhythm (`p-1.5`/`p-2.5` legacy micro-padding is grandfathered on untouched controls; new controls use the tokens below):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gap inside buttons/chips, FAQ row internal gap |
| sm | 8px | Compact element spacing, inline button rows, toast icon gap |
| md | 12px | FAQ Q&A input gap, category selector gap, table row action gap |
| base | 16px | Default element spacing, card/table cell padding |
| lg | 24px | Card padding inside editor panels/tab cards |
| xl | 32px | Space between editor sections, page header to first card |
| 2xl | 48px | Major section breaks (rare in admin) |
| 3xl | 64px | Not used on admin surfaces (public-page scale) |

Exceptions:
- **44px touch target:** admin-only controls are desktop-primary, but icon-only buttons (FAQ row delete, table row edit/delete) keep the existing `p-2`/`p-1.5` hit area; any control that becomes a primary mobile action (Re-sweep, Save/Publish) uses a **min-height of 44px** via padding — the only non-8pt exception, and it is a target not a gap.
- Input wells use `1px` borders (not a spacing value).

## Interaction Contract

Binding behavior for the executor (from D-01..D-16 + CONTEXT.md). This section is the machine-actionable half of the contract.

1. **Single canonical flow (D-01/D-02/CMS-05).** All create/edit/publish happens in `src/app/admin/page.tsx`. Delete `src/app/admin/articles/create/page.tsx` and `src/app/admin/articles/edit/[id]/page.tsx`. No nav element or link may point at `/admin/articles/create` or `/admin/articles/edit/*`.
2. **URL-state preserved (HYG-02 boundary).** `?tab=`, `?edit=`, `?preview=` behavior in `buildAdminUrl`/`navigate`/the restore `useEffect` is unchanged by this phase. New controls must not bypass `navigate()`.
3. **Shared auth fetch helper (D-03).** One helper attaches `Authorization: Bearer <token>` to every CMS call; on non-2xx it maps the status to the Copywriting rows above and raises the error toast; on 401 it clears the token and offers `Sign in`. It never returns silently and never leaves a spinner stuck.
4. **No empty editor (D-03/D-04).** Loading an existing article that returns non-2xx (404/403/401) renders the documented inline error panel, not a blank form. Proven end-to-end: reopen published article → mutate → save → reload shows mutations.
5. **GEO fields optional (D-09).** `focus_keyword`, `key_takeaways`, `entities`, `faq_schema` are optional and surfaced prominently in the editor; only `title`, `slug`, `content` are required, and `status` must be set. No client-side blocking on empty GEO fields.
6. **FAQ rows (D-10).** Add/remove repeating `{question, answer}` rows; incomplete rows are filtered out before the `faqSchema` payload is built; no public-side change.
7. **Taxonomy (D-12).** Level-1 category required (inline validation blocks save); Level-2 optional, filtered to the selected category's children, and reset to `''` when the parent changes. Hide the sub-select entirely when the parent has no children.
8. **RBAC UI hiding (D-13).** `NavItem` returns `null` for editor/author when `requiredRole="admin"`. Admin-only tabs: Insights, Insider, Taxonomy, Users, Blacklist, Affiliate Links, Settings. Editor/author see Dashboard + Article Management only. Backing routes keep their 403 enforcement (defense in depth, AUTH-02/03).
9. **User management scope (D-14).** Fields are `role` (admin/editor/author), `status` (active/inactive), `name`, `avatar` — **no password control**. `POST /cms/users` still accepts a password on create (a new account needs one), but the CMS must not offer password set/reset/change for existing users. Avatar falls back to the first letter of name/username (existing behavior).
10. **Inactive lockout (D-15).** Setting `status: 'inactive'` locks the account out immediately (enforced in `getAuthUser`). The edit modal warns before saving (copy above). No extra confirm dialog required — the action is reversible.
11. **Blacklist import is non-blocking (D-05).** The import request returns immediately with imported (and, if available, swept) counts; the sweep runs after the response. The success copy must not promise final sweep counts — see the eventual-count wording above. The import button disables and shows its spinner while the request is in flight.
12. **Sweep status semantics (D-07).** A swept campaign is `blacklisted`, distinct from a manually-set `inactive`. The admin Affiliate Campaigns view must present these as different states (blacklisted chips in rose, inactive in slate) so the two are never confused.
13. **Re-sweep is manual and reversible (D-08).** A `Re-sweep blacklist` control runs on the blacklist tab, re-runs the sweep over current entries, and restores campaigns currently `blacklisted` that no longer match any active entry back to `active` — never touching manually-set `inactive`. Report swept and restored counts per the Copywriting rows.
14. **Focus & keyboard.** All new controls are focusable with visible focus (`focus-visible:outline` in the block's hue); modal traps are inherited from the existing modal pattern; `Esc` closes modals via the existing close button behavior.
15. **Icon-only control labels (accessibility).** Every icon-only action carries both a `title` and an `aria-label` naming its target — the FAQ row delete pattern (`title="Remove this question"`, `aria-label="Remove FAQ row {index}"`) extends to the table row edit/delete icon buttons (`aria-label="Edit {name}"` / `aria-label="Delete {name}"`), the Re-sweep icon if rendered icon-only, and any new icon-only control added in this phase. An icon with no accessible name is a defect.
15. **Reduced motion.** The shell's `animate-in`/pulse/hover-scale motion is inherited; do not add new motion beyond the existing spinner.
