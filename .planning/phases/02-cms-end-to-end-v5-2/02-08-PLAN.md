## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin browser form → POST/PUT /api/v1/cms/sub-categories | A client-supplied `categoryId` string crosses into a Mongoose ObjectId ref write |
| Users tab → PUT /api/v1/cms/users/:id | An admin edits privilege-bearing fields (role/status) of another account |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-07 | Tampering | sub-categories POST/PUT `categoryId` | medium | mitigate | `Types.ObjectId.isValid(String(categoryId))` gate returns 400 before any DB write; regression test pins 400-not-500 |
| T-02-08 | Information Disclosure | sub-category 500 path leaking Mongoose CastError text | low | mitigate | The new 400 branch short-circuits before `create`/`save`, so the cast error path is not reached for a bad id |
| T-02-09 | Elevation of Privilege | Edit-user modal (role/status editing) | high | accept | Route enforcement already exists (PUT /cms/users/:id admin-only, pinned by cms-users-update.test.ts); this plan only makes the already-guarded control reachable and does not change the guard |
| T-02-10 | Spoofing | sub-category write principal | medium | mitigate | Both sub-category routes keep their existing `user.role !== 'admin'` 403 guard, unchanged by this plan |
| T-02-11 | Tampering | orphaned taxonomy data from a rejected write | low | mitigate | Invalid ids are rejected before assignment, so `category_id` is never set to a non-ObjectId value |

No new packages are added; no package-legitimacy checkpoint required (Mongoose/MongoDB — schema-gate not applicable).
</threat_model>
